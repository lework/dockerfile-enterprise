# 实践篇：部署代码依赖代理仓库

代理仓库将从公共源下载的依赖缓存在内网，减少开发和 CI 重复访问外部源。部分仓库也能托管私有包。离线构建前先用项目锁文件预拉取所需版本，再在隔离环境验证是否能构建。

本章用 Docker Compose 部署三个服务。先选访问方式，后续配置客户端和验证时沿用同一列。

| 服务 | 依赖 | 宿主机直连 | 经 Nginx 访问 |
| --- | --- | --- | --- |
| [goproxy](https://github.com/goproxyio/goproxy) | Go 模块 | `http://localhost:8082` | `http://goproxy.leops.local` |
| [Verdaccio](https://verdaccio.org/) | npm | `http://localhost:8083` | `http://verdaccio.leops.local` |
| [Sonatype Nexus Repository OSS](https://www.sonatype.com/nexus-repository-oss) | PyPI、Maven 和 Gradle | `http://localhost:8084` | `http://nexus.leops.local` |

使用 Nginx 时，先把三个域名解析到服务器，再按第二节配置站点。容器内的客户端使用从其网络可达的域名或宿主机地址。[模拟企业环境准备](30.实践篇-准备工作.md)

## 一、整合部署 (使用 Docker Compose)

在运行这三个服务的机器上，从仓库根目录进入配套编排目录。独立部署时，一起复制 `docker-compose.yml` 和 `verdaccio/conf/config.yaml` 并保留相对路径，然后从 Compose 文件所在目录运行后面的命令。[依赖代理编排](../docker-compose/dependency-proxies/docker-compose.yml) · [Verdaccio 配置](../docker-compose/dependency-proxies/verdaccio/conf/config.yaml)

```bash
cd docker-compose/dependency-proxies
docker compose config -q
docker compose up -d
docker compose ps
```

Go 代理在容器内监听 80 端口。公开模块请求转发到 `goproxy.io`，匹配 `git.leops.local` 前缀的请求由代理直连源站。客户端应先按第四节配置 `GOPRIVATE`，直接访问私有 GitLab。Go 镜像的入口程序使用 amd64 构建，在 ARM64 主机运行该服务需要 amd64 仿真支持。[Go 代理镜像定义](https://github.com/goproxyio/goproxy/blob/master/Dockerfile)

Verdaccio 允许匿名拉取，公开包从配置的 npm 上游下载并缓存，发布需要认证。直连访问和 Nginx 代理各使用客户端请求中的地址生成包链接。Nexus 首次启动需要完成初始化，再读取初始密码。

## 二、配置 Nginx 代理（模拟企业环境）

在 Nginx 服务器上，将 `goproxy.conf`、`verdaccio.conf` 和 `nexus.conf` 复制到 `/data/nginx/nginx_data/conf.d/`。各站点的 `proxy_pass` 指向服务所在宿主机，端口沿用表中的 8082、8083、8084。检查并重载 Nginx 后，继续配置 Nexus。[站点配置目录](../docker-compose/nginx/nginx_data/conf.d/)

```bash
docker exec nginx-proxy sh -c 'nginx -t && nginx -s reload'
```

## 三、配置 Nexus (用于 Python 和 Java)

先在 Nexus 宿主机读取初始密码，剩下的仓库配置在 Nexus 网页中完成。

1.  **获取初始管理员密码。** 等 Nexus 完成初始化，从依赖代理的 Compose 目录执行。
    ```bash
    # 等待 Nexus 完全启动 (可能需要几分钟)
    sudo cat ./nexus/data/admin.password
    ```
2.  **登录 Nexus。**
    - 从表中选择 Nexus 入口，用用户名 `admin` 和上一步获取的密码登录。
    - 首次登录需要修改密码。隔离的学习环境可以开启匿名读取，以便直接运行下面的无凭证示例。关闭匿名访问时，请为客户端配置有读取权限的账号。
3.  **配置 PyPI 代理和仓库组。**

    - 点击左侧菜单的齿轮图标 (Administration) -> Repositories。
    - 点击 "Create repository"。
      - 选择 "pypi (proxy)"。
      - **Name:** `pypi-proxy` (或其他你喜欢的名字)
      - **Remote storage:** `https://pypi.org/`（或组织已配置的 PyPI 上游）
      - **Blob store:** 默认即可。
      - 点击 "Create repository"。
    - 再次点击 "Create repository"。
      - 选择 "pypi (group)"。
      - **Name:** `pypi-group`
      - **Blob store:** 默认即可。
      - 将 `pypi-proxy` 加入 "Members"。如已创建用于托管私有包的 `pypi-hosted`，也可加入。
      - 点击 "Create repository"。
    - PyPI 客户端使用 Nexus 入口下的 `/repository/pypi-group/simple`。

4.  **配置 Maven 代理并加入仓库组。**

    - 点击 "Create repository" -> "maven2 (proxy)"。
      - **Name:** `maven-aliyun`
      - **Remote storage:** `https://maven.aliyun.com/repository/public/`
      - **Layout policy:** `Strict` (推荐)
      - 点击 "Create repository"。
    - 编辑预置的 `maven-public` 组，把 `maven-aliyun` 加入 "Members"。如所用镜像未预置该组，创建 `maven2 (group)` 并加入所需代理和托管仓库。[Nexus 默认仓库](https://help.sonatype.com/en/repository-types.html)
    - Maven 客户端使用 Nexus 入口下的 `/repository/maven-public/`。

## 四、配置客户端使用代理

复制命令前，按表选择客户端能访问的入口。以下示例采用模拟企业域名。宿主机直连时，改用对应的 `localhost:端口` 并保留仓库路径。Dockerfile 的 `RUN` 从构建容器发起请求，需使用该容器能访问的地址。

### Go 使用 goproxy

在运行 Go 命令的终端设置环境变量，再用一个公共模块验证下载。

  ```bash
  export GOPROXY=http://goproxy.leops.local,direct

  # 私有模块直连 GitLab，并跳过公共校验数据库
  export GOPRIVATE=git.leops.local

  go list -m golang.org/x/text@v0.3.2
  ```

`,direct` 仅在代理返回 404 或 410 时直连源站。使用私有模块时，在发起下载前设置 `GOPRIVATE`。如果学习环境的 GitLab 只提供 HTTP，只为该域名设置 `GOINSECURE=git.leops.local`。[Go 模块代理说明](https://go.dev/ref/mod#environment-variables)

### npm 使用 Verdaccio

- **在客户端验证。** 查询公开包版本，确认返回 `4.17.21`。

  ```bash
  npm view lodash@4.17.21 version --registry=http://verdaccio.leops.local/
  ```

- **在构建时使用。** 给 `npm install` 添加 `--registry` 参数，或在项目中保存 `.npmrc`。

  ```dockerfile
  # Dockerfile 示例
  RUN npm install --registry=http://verdaccio.leops.local

  # 或者 COPY .npmrc 文件
  # COPY .npmrc /app/.npmrc
  # RUN npm install
  ```

  `.npmrc` 文件内容：

  ```
  registry=http://verdaccio.leops.local
  ```

### pip 使用 Nexus 的 PyPI 代理

Linux 和 macOS 使用 `~/.config/pip/pip.conf` 或 `~/.pip/pip.conf`，Windows 使用 `%APPDATA%\pip\pip.ini`。也可以给单次 `pip install` 加 `-i`。

- **pip.conf / pip.ini:**

  ```ini
  [global]
  index-url = http://nexus.leops.local/repository/pypi-group/simple

  trusted-host = nexus.leops.local
  ```

- **Dockerfile 中:**

  ```dockerfile
  # Dockerfile 示例
  RUN pip install --no-cache-dir -i http://nexus.leops.local/repository/pypi-group/simple --trusted-host nexus.leops.local -r requirements.txt

  # 或者 COPY pip.conf 文件
  # COPY pip.conf /etc/pip.conf
  # RUN pip install --no-cache-dir -r requirements.txt
  ```

### Maven 使用 Nexus 的 Maven 代理

追加以下 `mirror` 到 Maven 的 `settings.xml` 中（通常在 `~/.m2/settings.xml`）。`mirrorOf` 为 `*` 时，请确认 Nexus 仓库组覆盖项目和插件依赖。[Maven 镜像设置](https://maven.apache.org/guides/mini/guide-mirror-settings.html)

- **settings.xml:**

  ```xml
  <settings xmlns="http://maven.apache.org/SETTINGS/1.0.0"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.0.0 http://maven.apache.org/xsd/settings-1.0.0.xsd">

    <mirrors>
      <mirror>
        <id>nexus</id>
        <name>Nexus Repository</name>
        <url>http://nexus.leops.local/repository/maven-public/</url>
        <mirrorOf>*</mirrorOf>
      </mirror>
    </mirrors>

  </settings>
  ```

- **Dockerfile 中:** 通常将配置好的 `settings.xml` 文件 `COPY` 到镜像中 Maven 使用的位置 (如 `/usr/share/maven/conf/settings.xml` 或 `/root/.m2/settings.xml`)。


## 五、验证 Nexus 代理

配置好两个仓库组后，从能访问 Nexus 的客户端执行。直连时将 `http://nexus.leops.local` 换成 `http://localhost:8084`。

```bash
curl -fsS -o /dev/null http://nexus.leops.local/repository/pypi-group/simple/requests/
curl -fsS -o /dev/null http://nexus.leops.local/repository/maven-public/org/apache/commons/commons-lang3/3.17.0/commons-lang3-3.17.0.pom
```

两条命令都应成功退出，分别验证 PyPI 的包索引和 Maven 的构件描述可以读取。到 Nexus 的 **Browse** 页面可查看缓存条目。
