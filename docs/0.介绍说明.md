# 关于这份指南

这份指南面向中小企业的开发人员、运维人员和技术负责人。开发人员可以按语言找到 Dockerfile 示例，学习怎样打包和运行应用。运维人员可以参考仓库部署、公共镜像维护和流水线配置。技术负责人可以从镜像分层、权限和版本管理着手制定团队约定。

第一次使用 Docker 时，先用 [README 的本地示例](../README.md) 构建一个镜像并运行容器。已经熟悉 Docker 的读者可以按当前任务选读下面的章节。

## 概念篇

[认识 Dockerfile](10.概念篇-认识Dockerfile.md) 解释镜像、容器和常用指令。[常见构建方式](11.概念篇-常见编译方式.md) 说明如何选择构建上下文、给镜像打标签，以及何时使用多阶段构建。

## 设计篇

[Dockerfile 编写规范](<20.设计篇-Dockerfile 编写规范.md>) 讨论怎样选择基础镜像、利用构建缓存和配置容器启动。[镜像分层与管理规范](<21.设计篇-Dockerfile 设计原则与镜像管理规范.md>) 说明如何复用团队的系统、工具和运行时镜像，以及如何命名、存储和更新镜像。

## 实践篇

从 [准备工作](30.实践篇-准备工作.md) 选择本机直连或通过 Nginx 访问内网服务的方式。

- 要为应用构建镜像，按 [README 的技术栈索引](../README.md#按技术栈构建应用) 找到 Go、PHP、Java、Python 或 Node.js 示例。各章会说明源码如何进入镜像，以及怎样确认容器已经正常运行。
- 要搭建团队环境，按需部署 GitLab、Harbor 和依赖代理。已有同类服务时，替换示例地址即可。准备好代码仓库和镜像仓库后，再跟随 [Jenkins 实践](<41.实践篇-使用 Jenkins 进行 CICD.md>) 完成一次构建和推送。
- 要制作团队共用的运维工具镜像，见 [构建运维工具](40.实践篇-构建运维工具.md)，其中包含 Ansible 和 Docker CLI 示例。

## 进阶篇

按维护任务选读 [漏洞扫描与修复](<50.进阶篇-扫描与修复 Docker 镜像漏洞.md>)、[镜像生命周期管理](<52.进阶篇-使用 Kaniko 在无 Docker Daemon 环境中构建镜像.md>) 或 [镜像签名](55.进阶篇-使用Notation签名镜像.md)。维护已有 Kaniko 流水线时，再看 [Kaniko 历史示例](51.进阶篇-kaniko编译镜像.md)。
