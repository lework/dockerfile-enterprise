# 实践篇：使用 Jenkins 进行 CI/CD

本章用 Jenkins 从 GitLab 拉取代码，把构建出的镜像推送到 Harbor 的 `dev` 项目，再从客户端拉回验证。先准备 GitLab 的示例仓库和可访问的 Harbor。[GitLab 实践](31.实践篇-部署代码仓库.md) · [Harbor 实战](32.实战篇-部署镜像仓库.md) · [Jenkins](https://www.jenkins.io/)

## 一、使用 Docker 部署 Jenkins

在运行 Jenkins 的机器上，使用仓库的 `docker-compose/jenkins` 目录。独立部署时，一并复制 `docker-compose.yml`、`Dockerfile` 和 `.dockerignore`，后续从目标 Compose 目录操作。[Jenkins 编排](../docker-compose/jenkins/docker-compose.yml) · [镜像定义](../docker-compose/jenkins/Dockerfile)

示例使用支持 Java 17 的最后一个 Jenkins LTS 版本 2.541.3。升级到 2.555.1 或更高版本前，一并检查控制器、执行节点和 CLI 的 Java 兼容性。[Jenkins Java 支持](https://www.jenkins.io/doc/administration/requirements/java/)

已有实例先确认当前版本，阅读跨越的 LTS 升级说明，备份 `./jenkins_home` 并用副本验证插件。完成验证后，在原部署目录更新文件，沿用同一数据目录和 8086、50000 端口。[Jenkins 升级指南](https://www.jenkins.io/doc/book/upgrading/) · [LTS 版本升级说明](https://www.jenkins.io/doc/upgrade-guide/)

Docker CLI 和 Buildx 安装在 Jenkins 容器中，通过 Docker socket 使用宿主机的 Docker Engine。能执行 Pipeline 的用户也能控制该 Engine。这套配置用于专用学习环境中的受信任作业。

启动前，分别检查两处的网络配置。

- **Jenkins 容器**解析 GitLab 等服务的域名。使用域名时，将 Compose 中 `extra_hosts` 的示例 IP 换成实际服务器 IP。使用 IP 直连时可去掉 `extra_hosts`。
- **Docker Engine**执行镜像拉取和推送。使用 Harbor 域名时，由内网 DNS 或引擎所在主机的 `hosts` 提供解析。使用 HTTP Harbor 时，为该引擎配置 `insecure-registries`。[Harbor 地址与引擎配置](32.实战篇-部署镜像仓库.md)

从仓库根目录执行。独立部署时，在 Compose 目录从第二行开始。

```bash
cd docker-compose/jenkins
docker compose config -q
docker compose up -d --build
docker compose exec jenkins docker version
docker compose exec jenkins docker buildx version
```

`docker version` 应同时显示客户端和服务端，`docker buildx version` 应显示 Buildx 版本。本机直连使用 `http://localhost:8086`，可直接进入第二节。

### 配置 Nginx 入口（模拟企业环境）

在运行 Nginx 的服务器上，将以下配置写入 `/data/nginx/nginx_data/conf.d/jenkins.conf`，把 `proxy_pass` 中的 IP 换成 Jenkins 宿主机 IP。

```nginx
server {
    listen 80;
    server_name jenkins.leops.local;

    location / {
        proxy_pass http://192.168.77.140:8086;
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

检查并重载 Nginx。

```bash
docker exec nginx-proxy sh -c 'nginx -t && nginx -s reload'
```

## 二、初始化 Jenkins

1. 在浏览器打开对应的 Jenkins 入口。本机直连使用 `http://localhost:8086`，经 Nginx 访问使用 `http://jenkins.leops.local`。
2. 在运行 Jenkins 的机器上，从 Jenkins Compose 目录读取初始密码，再用它解锁网页。

   ```bash
   docker compose exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
   ```

3. 安装推荐插件并创建管理员用户。将 Jenkins URL 设置为浏览器实际访问的地址。
4. 在 **Manage Jenkins → Plugins** 确认已安装 **Git**、**Pipeline** 和 **Docker Pipeline**。
5. 在 **Manage Jenkins → Nodes** 给能使用 Docker CLI 和 Engine 的执行节点添加 `docker-build` 标签。专用学习环境使用刚启动的 Jenkins 内置节点。

## 三、准备代码和凭证

在本机打开第 31 章克隆的 `my-first-app`。把下列内容保存为仓库根目录的 `Dockerfile`，提交并推送到 `main`。构建时，这个 Dockerfile 把仓库已有的 `README.md` 放入镜像。

```dockerfile
FROM nginx:1.27-alpine
COPY README.md /usr/share/nginx/html/README.md
```

在 Harbor 确认 `dev` 项目已创建，再创建项目机器人账号。该账号需要拉取和推送仓库的权限。[Harbor 项目机器人账号](https://goharbor.io/docs/main/working-with-projects/project-configuration/create-robot-accounts/)

在 Jenkins 的 **Manage Jenkins → Credentials** 添加两个 `Username with password` 凭证。Jenkins Docker Pipeline 的 `withRegistry` 依据该凭证类型认证。[Docker Pipeline 仓库认证](https://www.jenkins.io/doc/book/pipeline/docker/#using-a-custom-registry)

| ID | Username | Password |
| --- | --- | --- |
| `gitlab-credentials` | GitLab 用户名 | 有仓库读取权限的访问令牌 |
| `harbor-credentials` | Harbor 机器人账号全名 | 机器人密钥 |

## 四、创建并运行 Pipeline

在 Jenkins 选择 **New Item → Pipeline**，新建 `deploy-demo`。在 **Pipeline → Definition** 选择 **Pipeline script**，粘贴下面的示例，再按部署方式修改两处变量。

- `GITLAB_REPO_URL` 填实际的 HTTP 克隆地址。直连时，使用 Jenkins 容器能访问的宿主机 IP 和 8081 端口，并同步调整 GitLab 的 `external_url`。使用其他应用时，一并更新镜像引用中的 `my-first-app`。
- `DOCKER_REGISTRY` 填 Docker Engine 使用的仓库地址。直连 Harbor 时使用第 32 章配置的 `IP:8080`。

```groovy
pipeline {
    agent { label 'docker-build' }

    options {
        skipDefaultCheckout(true)
    }

    parameters {
        string(name: 'APP_GIT_BRANCH', defaultValue: 'main', description: 'Git 分支名，例如 feature/demo', trim: true)
    }

    environment {
        GITLAB_REPO_URL = 'http://git.leops.local/root/my-first-app.git'
        DOCKER_REGISTRY = 'harbor.leops.local'
        DOCKER_REGISTRY_SCHEME = 'http'
    }

    stages {
        stage('拉取代码') {
            steps {
                deleteDir()
                git branch: params.APP_GIT_BRANCH,
                    credentialsId: 'gitlab-credentials',
                    url: env.GITLAB_REPO_URL
            }
        }

        stage('构建并推送镜像') {
            steps {
                script {
                    def commit = sh(script: 'git rev-parse --short HEAD', returnStdout: true).trim()
                    def image = "${env.DOCKER_REGISTRY}/dev/my-first-app:${env.BUILD_NUMBER}-${commit}"
                    def registryUrl = "${env.DOCKER_REGISTRY_SCHEME}://${env.DOCKER_REGISTRY}"
                    docker.withRegistry(registryUrl, 'harbor-credentials') {
                        docker.build(image).push()
                    }
                    echo "已推送 ${image}"
                }
            }
        }
    }
}
```

保存后，首次点 **Build Now**，后续用 **Build with Parameters** 选择分支。镜像标签由 Jenkins 构建号和 Git 提交号组成，包含斜杠的分支名也能正常构建。项目稳定后，可把脚本保存为 `Jenkinsfile`，将 Definition 设为 **Pipeline script from SCM**。

## 五、验证交付结果

1. 在 Jenkins 的 **Console Output** 核对 Git 提交号、推送摘要和完整镜像引用。
2. 在 Harbor 的 `dev/my-first-app` 仓库核对同一个标签。
3. 从能访问 Harbor 的 Docker 客户端，用有拉取权限的账号登录并拉取。将下面的示例引用换成控制台实际输出的完整引用。

```bash
docker pull harbor.leops.local/dev/my-first-app:1-a1b2c3d
```

拉取成功后，GitLab 到 Harbor 的交付链路验证完成。运行环境的部署由后续流水线负责。
