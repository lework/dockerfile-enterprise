# 实践篇：构建标准化的 OS 基础镜像

本章构建一个 Debian 基础镜像，将系统证书、时区和常用工具统一配置。构建完成后，Harbor 中的 `common/os/debian:bullseye` 应同时提供 `linux/amd64` 和 `linux/arm64`，供后续语言镜像引用。分层原则见[第 21 章](21.设计篇-Dockerfile%20设计原则与镜像管理规范.md)。

## 一、如何选择基础 OS 镜像？

先按应用需要的 C 库、软件包和发行版维护周期筛选，再比较镜像体积和团队维护成本。

### 主流基础镜像对比

- **Alpine Linux (`alpine`):**

  - **优点:** 极其轻量（通常小于 10MB），启动快，攻击面小
  - **缺点:** 使用 `musl libc` 而非标准 `glibc`，可能导致某些软件存在兼容性问题；软件包管理工具 (`apk`) 与 Debian/Ubuntu 不同；社区和可用包相对较少
  - **适用场景:** 对镜像体积有极致要求，且应用兼容 `musl libc` 的场景

- **Debian (`debian`):**

  - **优点:** 非常稳定，社区支持良好，拥有庞大的软件包仓库，官方提供 `slim` 版本体积较小
  - **缺点:** 相较于 Alpine 体积较大
  - **适用场景:** 需要良好稳定性和广泛兼容性的生产环境

- **Ubuntu (`ubuntu`):**

  - **优点:** 源自 Debian，用户友好，社区庞大活跃，软件包更新快，硬件支持好
  - **缺点:** 相较于 Debian slim 和 Alpine 体积较大，默认安装可能包含更多服务
  - **适用场景:** 需要最新软件包、广泛社区支持的应用，开发环境常用

- **CentOS / Rocky Linux / AlmaLinux (`centos`, `rockylinux`, `almalinux`):**
  - **优点:** 企业级稳定性，与 RHEL 兼容
  - **缺点:** CentOS 7 已停止维护，CentOS Stream 定位变化；Rocky/AlmaLinux 相对较新；体积通常较大；包管理工具 (`yum`/`dnf`) 不同
  - **适用场景:** 对 RHEL 生态有依赖的企业环境

### 常用镜像对比

压缩大小以表中标签为例，实际值随架构与镜像更新而变化。

| 镜像 (示例标签)        | 大小 (压缩后) | C 库  | 包管理器 | 主要特点          |
| ---------------------- | ------------- | ----- | -------- | ----------------- |
| `alpine:latest`        | ~ 5-8 MB      | musl  | apk      | 极度轻量          |
| `debian:bullseye-slim` | ~ 30 MB       | glibc | apt      | 稳定、精简        |
| `ubuntu:latest`        | ~ 30 MB       | glibc | apt      | 流行、更新快      |
| `rockylinux:9-minimal` | ~ 40 MB+      | glibc | dnf      | RHEL 兼容、企业级 |

### 中小企业选择建议

1. **优先考虑官方 `slim` 版本:** 如 `debian:bookworm-slim`，它们在保持兼容性的同时减小了体积
2. **评估兼容性:** 如果应用对 C 库有特殊要求或依赖特定 glibc 功能，应避免使用 Alpine
3. **团队熟悉度:** 选择团队成员更熟悉的发行版（Debian/Ubuntu 系 vs RHEL 系）可以降低维护成本
4. **安全与更新:** 无论选择哪个，都要确保来源可靠（官方镜像），并建立机制定期更新基础镜像以获取安全补丁

> 后续章节沿用仓库中的 Debian 11 Bullseye 历史实验示例。Debian 已于 2026 年 8 月 31 日结束对 Debian 11 的 LTS。新部署请选择仍获安全更新的版本，并一起验证依赖该基座的工具层、运行时层和 APT 源。[Debian 公告](https://www.debian.org/News/2026/20260831)

## 二、制作标准化的 Debian 系统层镜像

系统层提供语言镜像共用的系统包。本例保留少量容器排查工具，编译器、语言运行时和应用专用组件交给工具层或运行层。

### 核心组件建议

- **证书:** `ca-certificates` (用于 HTTPS 连接)
- **时区:** `tzdata` (用于正确设置和显示时间)
- **本地化:** `locales`, `fonts` (用于支持不同语言环境，如 UTF-8)
- **网络工具:** `curl`, `wget` (用于下载文件)
- **系统管理工具:** `procps`, `psmisc`, `iproute2`, `telnet`, `vim-tiny`, `zip`, `unzip`, `inetutils-ping`, `tcpdump`, `lsof` (用于调试)

### 应避免在系统层安装的内容

- **完整编辑器:** 如需在容器中检查文件，本例只保留 `vim-tiny`
- **版本控制:** `git`
- **特定语言运行时或 SDK**

### 准备构建目录和 Dockerfile 前端

在 Linux 构建机上确认 Docker Engine、Buildx 和 GNU `date` 可用。先创建 Harbor 的 `library`、`common` 项目并确认当前账号有推送权限，再从本仓库根目录进入 [Debian 构建目录](../dockerfiles/common/os/debian/bullseye-slim/)。镜像仓库的地址、证书和实验 HTTP 设置见[第 32 章 Harbor](32.实战篇-部署镜像仓库.md)。

```bash
cd dockerfiles/common/os/debian/bullseye-slim
docker login harbor.leops.local

# 为与 Docker Engine 同架构的 BuildKit 同步 Dockerfile 前端
docker pull docker/dockerfile:1
docker tag docker/dockerfile:1 harbor.leops.local/library/docker/dockerfile:1
docker push harbor.leops.local/library/docker/dockerfile:1
```

上面的 `pull/tag/push` 只同步当前架构。若远程 builder 使用另一种架构，请在对应架构同步该前端，或让 builder 直接访问 Docker Hub 并将 Dockerfile 的 `# syntax` 指向 `docker/dockerfile:1`。

### Dockerfile 示例

在 `dockerfiles/common/os/debian/bullseye-slim` 使用下面的 `Dockerfile`。可按环境调整 APT 镜像地址，时区与字体配置会被后续镜像继承。

```Dockerfile
#syntax=harbor.leops.local/library/docker/dockerfile:1

ARG OS_VERSION=bullseye-slim

FROM debian:$OS_VERSION

ARG OS_VERSION

LABEL org.opencontainers.image.authors="ops.leops.local" \
      org.opencontainers.image.source="http://git.leops.local/ops/dockerfiles-base/common/os/debian/bullseye-slim/Dockerfile" \
      org.opencontainers.image.description="Standard Debian $OS_VERSION base image for internal use."

ENV LANG='en_US.UTF-8' \
    LANGUAGE='en_US.UTF-8' \
    TZ='Asia/Shanghai' \
    OS_VERSION=$OS_VERSION

WORKDIR /app

RUN sed -i -e 's#deb.debian.org#mirrors.aliyun.com#g' \
           -e 's#security.debian.org#mirrors.aliyun.com#g' \
           -e 's#ftp.debian.org#mirrors.aliyun.com#g' \
           /etc/apt/sources.list \
  && apt-get update \
  && apt-get install -y --only-upgrade $(apt-get --just-print upgrade | awk 'tolower($4) ~ /.*security.*/ || tolower($5) ~ /.*security.*/ {print $2}' | sort | uniq)  \
  && DEBIAN_FRONTEND=noninteractive DEBCONF_NOWARNINGS=yes apt-get install -y --no-install-recommends \
                        ca-certificates openssl \
                        tzdata wget curl procps psmisc dnsutils iproute2 telnet vim-tiny zip unzip inetutils-ping tcpdump lsof \
                        net-tools traceroute strace fonts-noto-cjk fontconfig locales \
  && sed -i -e 's/# en_US.UTF-8 UTF-8/en_US.UTF-8 UTF-8/' /etc/locale.gen \
  && dpkg-reconfigure --frontend=noninteractive locales \
  && update-locale LANG=en_US.UTF-8 \
  && fc-cache \
  && apt-get clean \
  && rm -rf /var/cache/apt/archives/* /var/lib/apt/lists/* /tmp/* /var/tmp/* \
  && truncate -s 0 /var/log/*log \
  && ln -sf /usr/share/zoneinfo/${TZ} /etc/localtime \
  && echo ${TZ} > /etc/timezone \
  && echo 'export PS1="\e[1;34m[\e[1;33m\u@\e[1;32m\h\e[1;37m:\w\[\e[1;34m]\e[1;36m\\$ \e[0m"' >> /etc/bash.bashrc
```

### Dockerfile 最佳实践要点

- **使用官方 Slim 镜像:** 选择 `debian:bullseye-slim` 作为基础
- **明确指定基础镜像版本:** 使用 `ARG` 变量便于后续更新
- **添加镜像元数据:** 使用 `LABEL` 记录镜像作者、来源等信息
- **设置必要环境变量:** 配置语言、时区等基础环境
- **合并 RUN 指令:** 将相关操作合并以减少镜像层数
- **使用 `--no-install-recommends`:** 减少不必要的依赖安装
- **清理缓存:** 删除 apt 缓存和临时文件减小镜像体积
- **配置国内镜像源:** 加速软件包下载
- **设置中文字体和本地化:** 支持中文显示和 UTF-8 编码

## 三、构建与推送镜像

### 配置 buildx 多平台构建环境

在同一台 Linux 构建机上创建 `docker-container` builder。已有同名实例可通过 `docker buildx use container-builder` 切换。使用实验 HTTP Harbor 时，先阅读下面的 registry 配置，再创建实例。

```bash
docker buildx create --name container-builder --driver docker-container --use --bootstrap
docker buildx inspect --bootstrap
```

从 `docker buildx inspect` 的 `Platforms` 确认两种目标架构都可用。使用实验 HTTP Harbor 时，把下面的段落写入 BuildKit 配置，创建 builder 时用 `--buildkitd-config` 指向该文件。Docker Engine 自己访问 HTTP Harbor 的设置见[第 32 章 Harbor](32.实战篇-部署镜像仓库.md)。

```toml
[registry."harbor.leops.local"]
  http = true
```

### 查看构建脚本

同目录的 `build.sh` 为两个目标架构构建并推送镜像。

```bash
#!/bin/bash

set -e

# 配置
REGISTRY="harbor.leops.local"
IMAGE_BASE_NAME="common/os/debian"
VERSION="bullseye-20250407-slim"


# 声明镜像地址数组
declare -a IMAGE_PATHS
IMAGE_PATHS+=(
    "${REGISTRY}/${IMAGE_BASE_NAME}:${VERSION}"           # 完整版本
    "${REGISTRY}/${IMAGE_BASE_NAME}:${VERSION%%-*}"       # 主版本
    "${REGISTRY}/${IMAGE_BASE_NAME}:${VERSION%%-*}-slim"  # 主版本
)


# 构建镜像
build_image() {

    echo "Building and pushing image:"
    for img in "${IMAGE_PATHS[@]}"; do echo -e " $img"; done

    docker buildx build --platform linux/amd64,linux/arm64 \
      $(for img in "${IMAGE_PATHS[@]}"; do echo "-t $img "; done) \
      --build-arg "OS_VERSION=${VERSION}" \
      --label "OS_VERSION=${VERSION}" \
      --label "org.opencontainers.image.created=$(date --rfc-3339=seconds)" \
      --provenance=false \
      --pull \
      --push \
      .

    echo "Build complete."
}


# 参数处理
case "$1" in
    "list-tags")
        # 输出镜像标签列表
        printf '%s\n' "${IMAGE_PATHS[@]}"
        ;;
    *)
    build_image
    ;;
esac
```

### 构建并核对多架构标签

在已登录 Harbor 的 Linux 构建机上，从包含 `Dockerfile` 和 `build.sh` 的 Debian 构建目录执行。

```bash
# 确保脚本有执行权限
chmod +x build.sh

# 在 Linux 构建机执行，脚本使用 GNU date
./build.sh

# 检查后续章节依赖的标签和两个目标架构
docker buildx imagetools inspect harbor.leops.local/common/os/debian:bullseye
```

看到 `common/os/debian:bullseye` 的平台列表同时有 `linux/amd64` 和 `linux/arm64` 后，再继续构建语言镜像。如果只出现一个平台，先核对当前 builder 的架构支持和构建日志。

### 版本控制

需要保存构建配置时，在有写权限的配置仓库中提交，先核对本次要提交的文件。

```bash
git add -A .
git commit -m "feat: add debian bullseye-slim"
git push
```
