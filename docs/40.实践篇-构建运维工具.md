# 实践篇：构建运维工具

按场景选择本章内容。Ansible 在容器里执行 Playbook，Docker CLI 为 CI 提供镜像构建命令，transfer.sh 是独立部署的文件传输服务。

构建前两种工具镜像时，先确认 Buildx 与 Harbor 可用。从本指南仓库根目录进入各自目录，保存这一节的 Dockerfile 和脚本，再运行 `bash build.sh` 推送镜像。运行工具时切换到 Playbook 或应用的工作目录。[第 32 章 Harbor](32.实战篇-部署镜像仓库.md)

## 1. Ansible 执行环境镜像

[Ansible](https://www.ansible.com/) 是一个广泛使用的 IT 自动化工具，用于配置管理、应用部署、任务编排等。构建一个包含 Ansible 的 Docker 镜像，可以方便地在 CI/CD 流水线或其他自动化脚本中调用 Ansible 来执行 Playbook，而无需在宿主机上安装 Ansible 及其依赖。

### 进入构建目录

前置镜像为 `harbor.leops.local/common/tools/python:3`，由[第 38 章](38.实践篇-构建%20Python%20应用程序镜像.md)的 Python 工具镜像构建脚本推送。

```bash
cd dockerfiles/common/tools/ansible
```

### Ansible Dockerfile

```Dockerfile
#syntax=harbor.leops.local/library/docker/dockerfile:1

FROM harbor.leops.local/common/tools/python:3

ARG ANSIBLE_VERSION=11.5.0

LABEL org.opencontainers.image.authors="ops@leops.local"  \
      org.opencontainers.image.source="http://git.leops.local/ops/dockerfiles-base/common/tools/ansible/Dockerfile" \
      org.opencontainers.image.description="Minimal base tools for ansible applications with non-root user."

RUN \
    set -exu; \
    # 创建非root用户，增强安全性
    groupadd -r nonroot; \
    useradd -r -m -g nonroot nonroot; \
    apt-get update; \
    # 安装基础工具和SSH客户端
    apt-get install -y --no-install-recommends \
            openssl \
            openssh-client; \
    # 安装指定版本的Ansible
    pip3 install --no-cache-dir ansible==${ANSIBLE_VERSION}; \
    # 验证安装并创建基础配置
    ansible --version; \
    mkdir /etc/ansible; \
    ansible-config init --disabled -t all > /etc/ansible/ansible.cfg; \
    # 清理临时文件，减小镜像体积
    apt-get clean; \
    rm -rf /var/cache/apt/archives/* /var/lib/apt/lists/* /tmp/* /var/tmp/*; \
    truncate -s 0 /var/log/*log;

# 切换到非root用户，提高安全性
USER nonroot:nonroot
```

### 构建并推送 Ansible 工具镜像

```bash
#!/bin/bash

set -e

# 配置
REGISTRY="harbor.leops.local"
IMAGE_BASE_NAME="common/tools/ansible"
VERSION="11.5.0"  # Ansible版本


# 声明镜像地址数组
declare -a IMAGE_PATHS
IMAGE_PATHS+=(
    "${REGISTRY}/${IMAGE_BASE_NAME}:${VERSION}"      # 完整版本号标签
    "${REGISTRY}/${IMAGE_BASE_NAME}:${VERSION%.*}"   # 次版本号标签
    "${REGISTRY}/${IMAGE_BASE_NAME}:${VERSION%%.*}"  # 主版本号标签
)


build_image() {

    echo "Building and pushing image:"
    for img in "${IMAGE_PATHS[@]}"; do echo -e " $img"; done

    # 构建镜像
    docker buildx build \
      $(for img in "${IMAGE_PATHS[@]}"; do echo -n "-t $img "; done) \
      --label "org.opencontainers.image.created=$(date --rfc-3339=seconds)" \
      --build-arg "ANSIBLE_VERSION=${VERSION}" \
      --add-host nexus.leops.local=192.168.77.140 \
      --provenance=false \
      --pull \
      --push \
      .

    echo "Build complete."
}

# 参数处理
case "$1" in
    "list-tags")
        # 输出镜像标签列表
        printf '%s\n' "${IMAGE_PATHS[@]}"
        ;;
    *)
    build_image
    ;;
esac
```

### 运行 Playbook

确认 Harbor 中已有 `common/tools/ansible:11.5.0` 后，到包含 `playbook.yml` 和 `inventory` 的目录执行。SSH agent 需要加载目标机使用的密钥，容器的 `nonroot` 用户需要能访问 agent 套接字，`known_hosts` 中要有目标机的公钥。执行后检查 Ansible 的任务汇总。

```bash
docker run --rm -it \
  --mount "type=bind,source=$PWD,target=/ansible" \
  --mount "type=bind,source=${SSH_AUTH_SOCK:?请先启动 SSH agent},target=/ssh-agent" \
  --mount "type=bind,source=$HOME/.ssh/known_hosts,target=/home/nonroot/.ssh/known_hosts,readonly" \
  -e SSH_AUTH_SOCK=/ssh-agent -w /ansible \
  harbor.leops.local/common/tools/ansible:11.5.0 \
  ansible-playbook -i inventory playbook.yml
```

## 2. Docker CLI 工具镜像 (用于 CI/CD)

在 CI/CD 流水线中，我们经常需要执行 Docker 命令来构建、推送或管理镜像和容器。虽然可以直接在 Runner 上安装 Docker，但有时使用一个包含 Docker CLI (和 buildx 插件) 的工具镜像会更方便、更隔离，并且能确保所有环境使用一致版本的 Docker CLI。

**重要提示:** 这种镜像**不包含** Docker 引擎本身。它需要通过挂载宿主机的 Docker Socket (`/var/run/docker.sock`) 来与宿主机的 Docker 引擎通信。这种方式称为 **Docker-out-of-Docker (DooD)**，它直接使用宿主机的 Docker 引擎和镜像缓存。允许访问 Docker Socket 的流水线也能控制宿主机的 Docker 服务，请仅在可信的 Runner 和流水线中使用。

### 进入构建目录

前置镜像为 `harbor.leops.local/common/os/debian:bullseye`。[第 34 章的 Debian 实验基座](34.实践篇-构建标准化的%20OS%20基础镜像.md)。

```bash
cd dockerfiles/common/tools/docker-cli
```

### Docker CLI Dockerfile

```Dockerfile
#syntax=harbor.leops.local/library/docker/dockerfile:1

FROM harbor.leops.local/common/os/debian:bullseye

ARG DOCKER_VERSION=28.1.1

LABEL org.opencontainers.image.authors="ops@leops.local"  \
      org.opencontainers.image.source="http://git.leops.local/ops/dockerfiles-base/common/tools/docker-cli/Dockerfile" \
      org.opencontainers.image.description="Docker CLI tools"

# 启用BuildKit以加速构建过程
ENV DOCKER_BUILDKIT=1

# 安装Docker CLI和buildx插件
RUN set -eux; \
    # 添加Docker官方源（这里使用阿里云镜像加速）
    echo "deb [trusted=yes] https://mirrors.aliyun.com/docker-ce/linux/debian bullseye stable" > /etc/apt/sources.list.d/docker-ce.list; \
    apt-get update; \
    # 安装Docker CLI和buildx插件，指定版本以确保一致性
    apt-get install -y -qq --no-install-recommends git docker-buildx-plugin docker-ce-cli=5:${DOCKER_VERSION}-1~debian.11~bullseye; \
    # 清理缓存文件，减小镜像体积
    apt-get clean; \
    rm -rf /var/cache/apt/archives/* /var/lib/apt/lists/* /tmp/* /var/tmp/*; \
    truncate -s 0 /var/log/*log;
```

### 从 CI 容器构建应用镜像

确认 Harbor 中已有 `common/tools/docker-cli:28.1.1`，再在 CI Runner 的应用代码根目录执行。宿主机的 Docker Engine 应出现构建结果 `myapp:ci-build`。

```bash
docker run --rm \
  -v /var/run/docker.sock:/var/run/docker.sock \
  --mount "type=bind,source=$PWD,target=/workspace,readonly" \
  -w /workspace \
  harbor.leops.local/common/tools/docker-cli:28.1.1 \
  docker build -t myapp:ci-build .
```

**安全提示:** 在生产环境中使用 DooD 模式时，建议：

1. 使用最小权限原则，只挂载必要的目录
2. 考虑使用 Docker 插件如`docker-socket-proxy`限制对 Docker Socket 的访问权限
3. 仅在可信环境中使用此方式

## 3. transfer.sh 文件传输服务

这一节使用 Docker Compose 部署 [transfer.sh](https://transfer.sh/)，上传文件存到宿主机 `/data/transfer/data`。下面的访问示例通过 Nginx 和 `transfer.leops.local`，先完成 Nginx 部署，并把域名指向代理宿主机。[第 30 章准备工作](30.实践篇-准备工作.md)

### 部署步骤

#### 1. 在服务宿主机创建数据目录

```bash
mkdir -p /data/transfer/data  # data目录用于存储上传的文件
cd /data/transfer
```

#### 2. 在服务目录保存 Compose 文件

将内容保存到 `/data/transfer/docker-compose.yml`。

```yaml
services:
  transfer:
    container_name: transfer
    image: dutchcoders/transfer.sh:latest
    command: --provider local --basedir /data/ --temp-path /data/
    restart: always
    ports:
      - '8085:8080' # 将容器的8080端口映射到主机的8085端口
    volumes:
      - ./data:/data # 挂载数据目录
      - '/usr/share/zoneinfo/Asia/Shanghai:/etc/localtime' # 设置正确的时区
```

#### 3. 启动服务

在 `/data/transfer` 执行。Nginx 将通过服务宿主机的 `8085` 端口访问容器。

```bash
docker compose up -d  # 后台运行服务
```

#### 4. 配置 Nginx 反向代理

在 Nginx 宿主机把配置保存到 `/data/nginx/nginx_data/conf.d/transfer.conf`。将 `proxy_pass` 的 IP 换成 Nginx 容器可访问的 transfer.sh 宿主机地址。

```nginx
server {
    listen 80;
    server_name transfer.leops.local;  # 服务域名，需要在DNS或hosts文件中配置

    access_log /var/log/nginx/transfer_access.log;
    error_log /var/log/nginx/transfer_error.log;

    location / {
        proxy_pass http://192.168.77.140:8085;  # transfer.sh服务地址和端口
        proxy_set_header  Host              $http_host;
        proxy_set_header  X-Real-IP         $remote_addr;
        proxy_set_header  X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header  X-Forwarded-Proto $scheme;

        # 关闭缓冲，适用于文件传输场景
        proxy_buffering off;
        proxy_request_buffering off;

        # 设置较长的超时时间，适合大文件传输
        proxy_send_timeout 900;
        proxy_read_timeout 900;
    }
}
```

保存后在 Nginx 宿主机执行。配置检查通过才会重载。

```bash
# 在运行 Nginx 的服务器上执行
docker exec nginx-proxy sh -c "nginx -t && nginx -s reload"
```

### 使用示例

在能解析 `transfer.leops.local` 的客户端目录准备 `myfile.txt`，运行下面的命令上传再下载。完成后检查 `downloaded-myfile.txt` 内容是否与源文件一致。

```bash
# 上传文件，返回一个下载链接
download_url="$(curl -fsS --upload-file ./myfile.txt http://transfer.leops.local/myfile.txt)" &&
  curl -fsS "$download_url" -o downloaded-myfile.txt

# 也可以通过浏览器访问服务并上传下载文件
# 在浏览器中打开: http://transfer.leops.local
```
