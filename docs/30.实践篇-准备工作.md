# 实践篇：准备工作

只想练习 Dockerfile 构建时，在自己的电脑上选路径一。想练习代码仓库、镜像仓库、依赖代理和 CI/CD 如何配合时，选路径二，在 Linux 服务器上部署并通过内网域名访问。

## 路径一：本地学习环境

1. 安装 Docker。Windows 和 macOS 使用带有图形界面的 Docker Desktop。Linux 按发行版安装 Docker Engine，同时安装 Buildx 和 Compose 插件。[Docker Desktop](https://www.docker.com/products/docker-desktop/) · [Docker Engine](https://docs.docker.com/engine/install/)
2. 安装 Git，用于拉取指南和示例代码。可选装自己熟悉的代码编辑器。[Git 安装包](https://git-scm.com/downloads) · [Visual Studio Code](https://code.visualstudio.com/)

通过文末的工具检查后，可先运行 README 的本地构建示例。第 34–40 章的分层构建使用示例 Harbor 和依赖代理，跟做前准备好对应服务，或换成已有的仓库和代理地址。[本地构建示例](../README.md)

需要在本机部署配套服务时，GitLab 使用 8081 端口，Jenkins 使用 8086 端口。Harbor 的 IP 或域名需要能从 Docker Engine 访问。[Harbor 地址设置](32.实战篇-部署镜像仓库.md)

## 路径二：模拟企业环境

1.  **准备 Linux 服务器。**

    - **系统:** 选择 Docker Engine 支持的 Debian 或 Ubuntu 版本，见下面的安装文档。
    - **资源:** 按实际运行的服务预留 CPU、内存和磁盘。GitLab、Harbor、Nexus 可以分开部署和练习。
    - **权限:** 需要有 `sudo` 或 `root` 权限。

2.  **规划内网域名。** 使用域名入口时，在服务器和访问服务的电脑上配置 `hosts`，让域名指向 Linux 服务器。Linux 和 macOS 使用 `/etc/hosts`，Windows 使用 `C:\Windows\System32\drivers\etc\hosts`。把示例中的 `192.168.77.140` 换成实际服务器 IP。

    `git`、`harbor` 和 `jenkins` 分别对应代码仓库、镜像仓库和 CI/CD。`nexus` 代理 PyPI 和 Maven，`verdaccio` 代理 npm，`goproxy` 代理 Go 模块。

    ```
    192.168.77.140 git.leops.local
    192.168.77.140 harbor.leops.local
    192.168.77.140 jenkins.leops.local
    192.168.77.140 nexus.leops.local
    192.168.77.140 verdaccio.leops.local
    192.168.77.140 goproxy.leops.local
    ```

    容器内的域名解析需单独配置。后续会用 Nginx 为这些域名转发流量，用内网 DNS 或 Compose 的 `extra_hosts` 让需要主动访问这些域名的容器完成解析。

3.  **在 Linux 服务器上安装 Docker Engine。** 按发行版使用官方安装步骤，并安装 `docker-buildx-plugin` 和 `docker-compose-plugin`。[Debian 安装说明](https://docs.docker.com/engine/install/debian/) · [Ubuntu 安装说明](https://docs.docker.com/engine/install/ubuntu/)

    已有 Docker 配置需要调整时，将新设置合并进现有 `daemon.json`。镜像加速可按需参考[第 54 章](54.进阶篇-Docker%20镜像代理加速器配置指南.md)。

4.  **在 Linux 服务器上安装 Git。**

    ```bash
    sudo apt-get update
    sudo apt-get install -y git
    ```

5.  **启动 Nginx。** 在 Linux 服务器上检出本仓库，从仓库根目录执行下面的命令，放入主配置和默认站点。各服务章节再按需添加站点配置。

    ```bash
    sudo mkdir -p /data/nginx/nginx_data/{conf,conf.d,logs}
    sudo cp docker-compose/nginx/docker-compose.yml /data/nginx/
    sudo cp docker-compose/nginx/nginx_data/conf/nginx.conf /data/nginx/nginx_data/conf/
    sudo cp docker-compose/nginx/nginx_data/conf.d/default.conf /data/nginx/nginx_data/conf.d/
    cd /data/nginx
    sudo docker compose config -q
    sudo docker compose up -d
    curl -fsS http://127.0.0.1/healthz
    ```

    返回 `healthy` 表示默认站点可访问。添加其他站点时，将示例 `proxy_pass` 中的 `192.168.77.140` 换成 Nginx 容器可访问的服务宿主机 IP。

## 验证工具

在运行后续构建命令的机器上执行。

```bash
docker version
docker compose version
docker buildx version
git --version
```

确认 `docker version` 同时显示客户端和服务端。Linux 上如需 `sudo` 才能访问 Docker Engine，运行后续 Docker 命令时也加上 `sudo`。
